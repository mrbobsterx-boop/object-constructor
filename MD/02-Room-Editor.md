# Room Editor — справочник

Редактор **комнат**: размещает объекты из каталога Object Constructor на холсте, размечает зоны, настраивает фоны, свет, двери и разрушаемые блоки (грунт и стены). Результат — `data/rooms/<id>.json`, который читают Building Editor и игра (Godot).

- Файл запуска: `index.html` (двойным кликом, `file://`; нужен Chrome/Edge — File System Access API).
- Скрипты — обычные `<script>` с **общей глобальной областью видимости** (без `import`/`export`): функции и переменные разных файлов видят друг друга. Номер файла = порядок загрузки; `16-init.js` — всегда последним.

---

## 1. Что умеет редактор

### Холст
- Комната рисуется на холсте в пикселях редактора (**100 px = 1 м**). Масштаб — Ctrl+колесо (10 %…600 %), панорамирование — правая кнопка мыши. Вокруг комнаты показываются размерные линии («ширина: X м», «высота: Y м»).
- Размер комнаты задаётся в **метрах** (поле «Размер комнаты», по умолчанию 6,4 × 2,2 м).

### Объекты
- **Библиотека** слева (поиск, категория) — объекты из `data/objects/*.json`. Список категорий **динамический**: берётся из `data/categories.json` (его пишет ОС, порядок и названия как в ОС) и дополняется категориями, которые встречаются у объектов; рядом с названием — число объектов, выбор сохраняется при «🔄 Обновить библиотеку». У карточки объекта показывается русское название категории. Объект перетаскивается на холст. У объекта без картинки показывается заглушка; на холсте — пунктирная рамка его размера.
- **Размер объекта** задаёт ОС (целые см). При открытии комнаты каждый экземпляр получает **актуальный размер из ОС**; если он изменился, в строке статуса появится сообщение — комнату нужно сохранить, чтобы записать новый размер. Размер, записанный в комнате, используется только если объекта нет в каталоге или в ОС размер не задан. Кнопка **«📐 Размеры из ОС во всех комнатах»** (под библиотекой) пробегает все сохранённые комнаты и записывает актуальные размеры в их файлы (у `FLOOR_ONLY`-объектов нижняя грань остаётся на месте, у остальных — центр; комнаты старого формата пропускаются).
- Объект можно двигать, поворачивать и масштабировать ручками (углы — масштаб, верхний кружок — поворот), выбирать, копировать свойства в панели справа.
- **Панель свойств** (справа): позиция X/Y (м), «Размер в игре» (см, только чтение), масштаб %, поворот, flip ↔/↕, декор, порядок (на передний/задний план, число Z), режим плотности (`ZLEVEL` / `SOLID` / `NONE`), источник света, тень, дверь.
- **Декор** (`isDecor`) — игнорирует зоны, опору и коллизии; ставится куда угодно.
- **Режим размещения** объекта берётся из ОС: `ANYWHERE` или `FLOOR_ONLY` (падает на твёрдую опору и двигается по горизонтали/поднимается на опору).
- **Свет**: круг или конус; радиус (м), цвет, интенсивность, направление/раскрытие/размытие. **Тень**: поглощение света; превью теней приближённое — настоящие тени считает Godot.
- **Дверь**: `toRoom` (id комнаты назначения) и точка появления `spawnX/spawnY` в метрах.
- **Множественное выделение**: рамкой по пустому месту. Выделенное можно удалить или сохранить как **набор (set)** — заготовка из нескольких объектов/фонов, которую вставляют в центр другой комнаты.

### Зоны и полоса ходьбы
- Пол разбит на клетки 10×10 см. Цвета: **красный** — твёрдая поверхность, **зелёный** — можно ставить объекты, **оранжевый** — нельзя строить/интерактив.
- По умолчанию клетки на уровне и ниже линии, лежащей на **0,9 м выше низа комнаты** (`walk_line_bottom_m` из настроек проекта), красные (пол), выше — зелёные. Ручная разметка кистями (красный/зелёный/оранжевый/ластик) перекрывает дефолт. **Твёрдые куски блоков тоже считаются красной зоной** (см. «Блоки»): на них встают объекты, внутрь ставить нельзя.
- **Полоса ходьбы** — синяя полоса толщиной N см (по умолчанию 20) над этой линией; вручную не размечается.
- Сетка/зоны включаются кнопкой или Ctrl+G; линии каждые 10 см, метровые — толще.

### Проверка размещения
Объект (не декор) считается **корректным**, если: все клетки под ним зелёные и он внутри комнаты; нет коллизии с другими объектами (`collisionMode` не `NONE`, не декор); для `FLOOR_ONLY` есть твёрдая опора на всю ширину. Блоки участвуют в проверке как красная зона: объект, оказавшийся внутри блока, некорректен. После правки блоков объекты **не двигаются** (гравитацию считает игра), пересчитывается только подсветка. Некорректный объект подсвечивается красным; при сохранении комнаты редактор показывает список проблем и просит подтверждение.

### Фоны комнаты
Несколько слоёв (параллакс): картинка, прозрачность, «скорость параллакса» (использует Godot), flip, порядок. Новый слой вписывается по ширине комнаты. Слои можно двигать/масштабировать/вращать ручками.

### Композиция и лестницы
- **Роль комнаты в здании** (сетка 3×3: `TOP_LEFT … BOTTOM_RIGHT`, по умолчанию `CENTER_CENTER`) — для генерации зданий.
- **Лестничные точки** (6 вариантов: верх/низ × лево/центр/право) — координаты фиксированы: 1,5 м от края или по центру; на холсте рисуются маркеры ↑/↓.

### Генерация
- **«Сгенерировать похожую»**: по образцам (статистика по сохранённым комнатам типа: как часто встречается объект/группа и где стоит) или по **рецепту** (явный список «что и сколько» по типу комнаты). Опция «добавить к текущим», размер новой комнаты; при генерации по образцам (без «добавить») фон берётся случайно из образца.
- **«Рецепты комнат»**: строки `группа взаимозаменяемости, от, до`; строка без группы = любой декор, разрешённый для типа комнаты. Хранятся в `data/room_recipes.json`.

### История
Undo/redo (до 30 шагов): ↶/↷ и Ctrl+Z / Ctrl+Shift+Z (Ctrl+Y). Delete/Backspace — удалить выбранный объект; стрелки — сдвиг на 1 px (Shift — 10 px). Хоткеи не действуют, пока курсор в поле ввода.

### Блоки: разрушаемый грунт и стены (панель «🧱 Блоки», модуль 15)
- **Блок 1×1 м** (100×100 px) = **5×5 кусков по 20×20 см**. Куски ломаются по одному (в игре), поэтому у блока есть **маска** (25 бит: бит `py*5+px` = 1 — кусок на месте). **В редакторе блоки ставятся только целыми**, рамкой по сетке 1 м, всегда встык, без зазоров; частично разрушенные блоки рисовать нельзя (их создаёт игра).
- **Тип блока** — объект ОС категории **«Блок / материал»** (`block`; переключатель «все объекты» показывает остальные). Справа — палитра с **картинками** типов блоков: клик выбирает тип для рисования (список `blockTypeSelect` синхронизирован). Картинка блока — основная картинка объекта; каждый кусок берёт свою 1/5×1/5 часть текстуры.
- Инструменты (рамкой по сетке): «Рисовать», «Стереть», «Залить комнату», «Очистить»; «🔍 Вписать» вписывает комнату в экран.
- **Твёрдость.** Клетка внутри существующего куска — красная зона (обёртка над `zoneColorAt`). Так `FLOOR_ONLY`-объекты встают на грунт, внутрь блока объект поставить нельзя, а оверлей зон показывает блоки. Объекты в редакторе не «падают», если убрать грунт: они только подсвечиваются, если оказались внутри блока.
- **Срез углов.** Внешние (торчащие) углы массива блоков срезаются фаской: угол куска срезается, если **оба** соседних по стороне куска отсутствуют; внутренние углы прямые. Размер среза — `block.bevel_px` материала или общий `block_bevel_px` проекта (поле «Срез угла блока (px)» рядом с настройками проекта, по умолчанию 4 px). У границы комнаты срез не рисуется (сосед может продолжать грунт). Срез — только внешний вид, collision остаётся квадратной.
- Блоки рисуются одним canvas на всю комнату (кэшируется, перерисовывается только при изменении блоков, картинок или среза).
- Копать можно куда угодно, в том числе через границу комнаты; комнаты с блоками должны иметь целые размеры, а в здании стоять на целом метре (Building Editor следит за этим).
- **Окружения 3×3 (`world.neighbors`) больше нет** — секция, «Проверить связи» и «Проставить обратные» удалены. Старый ключ читается и отбрасывается при сохранении.

## 2. Данные

**Читает:**

| Путь | Зачем |
|---|---|
| `data/objects/*.json` + `assets/sprites/…` | каталог объектов и их картинки (библиотека, размеры, свет, тени, режим размещения; палитра блоков и их картинки, `block.bevel_px`) |
| `data/categories.json` | список категорий для фильтра библиотеки (пишет ОС) |
| `data/rooms/*.json` | открыть комнату; список комнат для дверей; образцы для генератора |
| `data/sets/*.json` | готовые наборы |
| `data/project_settings.json` | `walk_line_bottom_m` (общая для проекта линия ходьбы), `block_bevel_px` (срез углов блоков) |
| `data/room_recipes.json` | рецепты генерации |

**Пишет:**

| Путь | Когда |
|---|---|
| `data/rooms/<id>.json` | «💾 Сохранить комнату»; «📐 Размеры из ОС во всех комнатах» переписывает `realWidthCm/realHeightCm` (и `yM` у `FLOOR_ONLY`) в **чужих** комнатах, с подтверждением |
| `assets/sprites/rooms/<файл>` | вместе с комнатой — картинки фоновых слоёв |
| `data/sets/<id>.json` | «Сохранить как сет» |
| `data/project_settings.json` | «💾 Сохранить настройки проекта» — пишет `walk_line_bottom_m` и `block_bevel_px`, остальные ключи файла сохраняются |
| `data/room_recipes.json` | «💾 Сохранить рецепт» |

### Формат комнаты `data/rooms/<id>.json` (`schema_version: 4`)

Длины в **метрах** (суффикс `M`), размеры объектов — в **сантиметрах** (`…Cm`).

```json
{
  "schema_version": 4, "id": "kitchen_01", "name": "Кухня", "type": "kitchen",
  "widthM": 6.4, "heightM": 2.2, "playerWalkZ": 10, "walkLineThicknessCm": 20,
  "zoneCells": { "12,3": "RED", "13,3": "ORANGE" },
  "compositionRole": "CENTER_CENTER",
  "stairConnections": [ { "type":"STAIR", "position":"TOP_LEFT", "direction":"UP" } ],
  "backgroundLayers": [ { "image":"rooms/kitchen_01_bg1.png", "opacity":1, "parallax":1,
        "xM":3.2, "yM":1.1, "widthM":6.4, "heightM":2.2, "rotation":0, "flipH":false, "flipV":false } ],
  "instances": [ { "instanceId":"inst_…", "objectId":"table_01", "xM":2.5, "yM":1.6, "scale":1,
        "rotation":0, "flipH":false, "flipV":false, "zIndex":10, "collisionMode":"ZLEVEL",
        "light":null, "shadow":null, "isDecor":false, "placementMode":"FLOOR_ONLY",
        "realWidthCm":120, "realHeightCm":80, "door":null } ],
  "world": { "blockSizeM":1, "pieceSizeM":0.2,
        "blocks": [ {"cx":0,"cy":2,"type":"dirt"}, {"cx":1,"cy":2,"type":"dirt","mask":33553407} ] }
}
```
- `xM/yM` объекта и слоя фона — **центр**; `zoneCells` — ключ `"cx,cy"`, клетки 10×10 см, значения `RED`/`GREEN`/`ORANGE`.
- У света в комнате: `light:{radiusM,color,intensity,shape,angle,spread,softness}`; у двери: `door:{toRoom,spawnXM,spawnYM}`.
- `world` пишется, только если в комнате есть блоки: `{blockSizeM:1, pieceSizeM:0.2, blocks:[{cx,cy,type,mask?}]}`. `cx,cy` — **индексы** клетки 1×1 м от левого верхнего угла комнаты, `type` — id объекта-материала, `mask` — 25 бит кусков (нет ключа — блок целый, `33554431`). Старый формат (`state`, `neighbors`) читается: `INTACT`/`DAMAGED` дают целый блок, `DESTROYED`/`ABSENT` — пустоту; `neighbors` отбрасывается.
- Старые файлы (px при 640 px/м, `schema_version < 4`) читаются и пересчитываются автоматически.

### Формат набора `data/sets/<id>.json` (`schema_version: 2`)
`objects[]` (позиции `xM/yM` относительно левого верхнего угла рамки выделения), `background_layers[]` — служебный формат редактора, игра его не читает.

## 5. Справочник функций

### 01-core-utils.js

| Функция | Что должна делать |
|---|---|
| `sanitizeSlug(s)` / `translit(str)` / `esc(s)` | Безопасный id из строки / транслитерация кириллицы / экранирование HTML |
| `dataURLToBytes(dataURL)` | data URL → `Uint8Array` (для записи PNG на диск) |
| `pxToM(px, digits=2)` / `mToPx(m)` | px ↔ метры (метры — с точностью до 1 см; `mToPx` убирает шум плавающей точки) |
| `lenPx(o, mKeys, legacyKey, fallbackPx, legacyPPM)` | Длина из JSON в px: ключ в метрах → старый ключ в px (÷640; для радиусов света ÷100) → запасное значение |
| `lightFromJSON(l)` / `lightToJSON(l)` | Свет: JSON (`radiusM` / `radius_m` объекта / старый `radius`) ↔ внутренний вид (`radius` в px) |
| `doorFromJSON(d)` / `doorToJSON(d)` | Дверь: `spawnXM/spawnYM` в метрах ↔ `spawnX/spawnY` в px |
| `bgScaleFromJSON(l, nativeW)` | Масштаб фона: `widthM·100 / ширина_картинки`; для старых файлов `scale·100/640` |
| `roomFromJSON(d)` | Приводит JSON комнаты (новый/старый, вплоть до самого старого «один фон») к единому виду в px |
| `idbOpen/idbSet/idbGet` | Хранилище IndexedDB `room_editor_fs` для дескриптора папки |
| `getSubdir(root, path, create)` | Заходит в подпапки по пути; при `create` создаёт |
| `writeFileToProject(relPath, bytes)` | Пишет файл в проект (создаёт папки); `false`, если папка не подключена |
| `updateFolderStatus(needsRegrant)` | Статус папки в шапке, кнопка «Разрешить доступ» |
| `connectProjectFolder()` | Выбор папки; затем грузит настройки, рецепты, каталог объектов, комнаты, наборы |
| `tryRestoreProjectFolder()` | При старте восстанавливает папку; если права уже есть — грузит данные |
| `regrantProjectFolder()` | Запрашивает права и перечитывает данные |

### 02-catalog.js

| Функция | Что должна делать |
|---|---|

## 6. Известные особенности

- Внутри редактора всё в px, в JSON — метры; переводить нужно только на границах (сохранение, загрузка, поля ввода).
- Блоки участвуют в проверке размещения и в зонах (твёрдый кусок = красная клетка). Объекты при правке грунта **не двигаются**: `FLOOR_ONLY`-объект, потерявший опору, в редакторе остаётся на месте (гравитацию и урон от падения считает игра).
- Картинки блока — только его основная картинка (`appearance.asset`); `destruction.damaged/broken.image` Room Editor больше не читает.
- Размер комнаты с блоками должен быть кратен 1 м — иначе крайние блоки выступают за границу (в сводке появится предупреждение).
- Категория `block` (id) зашита в коде модуля 15; список категорий библиотеки — динамический.
- Копия комнаты («Дублировать») оставляет блоки.
- Срез углов — только внешний вид; у границы комнаты его нет, в игре срез считают по данным соседней комнаты.
- `image-rendering: pixelated` на объектах: крупные картинки при уменьшении выглядят «зубчатыми».
- Размер экземпляра в файле комнаты (`realWidthCm/realHeightCm`) — копия на момент сохранения; актуальный размер подставляется при открытии, а все файлы сразу обновляет кнопка «📐 Размеры из ОС во всех комнатах» (`syncAllRoomSizes()` в модуле 11).
