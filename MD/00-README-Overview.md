# Редакторы игры — обзор

Три HTML-редактора работают с одной **папкой проекта** и передают друг другу данные через JSON-файлы. Два вспомогательных приложения не редактируют игровые данные: **реестр** читает всю папку проекта и показывает, что в ней есть, кто на кого ссылается и что сломано; **Object Plan** — чек-лист объектов, которые ещё нужно создать в ОС, с отметками о выполнении. Игра (Godot) читает те же файлы.

| Документ | Приложение | Делает |
|---|---|---|
| [01-Object-Constructor-OS.md](01-Object-Constructor-OS.md) | **ОС** — Universal Object Constructor | Объекты и материалы блоков: картинки, анимации, поведение, разрушение, крафт → `data/objects/*.json`; список категорий → `data/categories.json` |
| [02-Room-Editor.md](02-Room-Editor.md) | **Room Editor** | Комнаты из объектов: зоны, свет, двери, фоны, разрушаемые блоки → `data/rooms/*.json` |
| [03-Building-Editor.md](03-Building-Editor.md) | **Building Editor** | Здания и улицы из комнат → `data/buildings/*.json` |
| [04-Project-Registry.md](04-Project-Registry.md) | **Project Registry** | Реестр всего проекта: списки, связи, проверки. Только читает |
| [05-Object-Plan.md](05-Object-Plan.md) | **Object Plan** | Чек-лист объектов для создания в ОС: зачем нужен, функция, вариации, параметры, связи, порядок создания; автоматические отметки по проекту. Пишет только `data/object_plan.json` |
| [UNITS.md](UNITS.md) | — | Единицы измерения, формат блоков, формулы для Godot |

## 1. Поток данных

```
   ОС  ──────────►  Room Editor  ──────────►  Building Editor  ──────►  Godot
 объекты            комнаты                    здания / улицы
 материалы блоков   data/rooms                 data/buildings
 data/objects       (блоки, двери, зоны)
 data/categories.json
 assets/sprites     assets/sprites/rooms       assets/sprites/rooms/building_backgrounds

            Project Registry  ◄── читает всё: data/**, assets/** (ничего не пишет)
            Object Plan  ◄── читает data/objects, data/rooms, assets/sprites; пишет только data/object_plan.json
```

Каждый следующий редактор **читает** результат предыдущего (каталог объектов → библиотека комнаты; каталог комнат → план здания), но не меняет его. Редакторы пишут только свои файлы; служебные исключения: ОС пишет ещё `data/categories.json`, Room Editor — `data/project_settings.json`, `data/room_recipes.json`, `data/sets/*`.

## 2. Папка проекта

Все приложения подключают **одну и ту же** папку кнопкой «📁 Подключить папку проекта» (Chrome/Edge; дескриптор запоминается в IndexedDB, при следующем запуске нужно только подтвердить доступ).

```
<проект>/
├── data/
│   ├── objects/<id>.json          ← ОС (в т.ч. материалы блоков, категория block)
│   ├── categories.json            ← ОС: список категорий [{id,name}] (читают Room Editor и реестр)
│   ├── rooms/<id>.json            ← Room Editor
│   ├── sets/<id>.json             ← Room Editor (наборы, служебные)
│   ├── buildings/<id>.json        ← Building Editor
│   ├── project_settings.json      ← Room Editor: walk_line_bottom_m, block_bevel_px
│   ├── room_recipes.json          ← Room Editor: рецепты генерации
│   ├── object_plan.json           ← Object Plan: отметки о выполнении (необязательный)
│   ├── characters/, rigs/, parts/ ← Character Assembler (ОС и реестр только читают)
├── assets/
│   ├── sprites/
│   │   ├── <категория>/…png       ← ОС: картинки, листы анимаций, состояния
│   │   └── rooms/…png             ← Room Editor: фоны комнат
│   │       └── building_backgrounds/…  ← Building Editor: фоны зданий
│   └── sounds/…                   ← ОС
```

## 3. Единицы измерения

**В данных — игровые метры; пиксели только внутри редакторов для отображения (`100 px = 1 м`, 1 px = 1 см).**

| Что | Единица в JSON | Ключи |
|---|---|---|
| Комнаты | метры, суффикс `M` | `widthM, heightM, xM, yM, radiusM, spawnXM, spawnYM` |
| Здания | метры, суффикс `_m` | `x_m, y_m, width_m, height_m, crop_m` |
| Объекты | метры / м/с, суффикс `_m` / `_mps` | `radius_m, range_m, speed_mps` |
| Размер объекта | **сантиметры (целые)** | `real_width_cm, real_height_cm, realWidthCm, walkLineThicknessCm` |
| Картинка | px исходной картинки (не мировые) | `imageWidth, imageHeight, collision.rect` |
| Клетки зон | индекс клетки 10×10 см | `zoneCells: {"cx,cy": "RED"}` |
| Блоки | индекс клетки 1×1 м; кусок 20×20 см — маска 25 бит | `world.blocks[].cx, cy, mask` |
| Материал блока | см / px (= см) / доля 0…1 | `block.piece_size_cm, block.bevel_px, block.drop_table[].chance` |

**Размер объекта** задаётся только в ОС (целые сантиметры) и не зависит от пикселей картинки. Картинка растягивается ровно под ширину×высоту, поэтому в ОС по умолчанию включена кнопка «🔗 Сохранить пропорции»: при вводе ширины высота подставляется по пропорциям картинки, и наоборот. Если размер не задан (0), редакторы берут размер картинки как 1 px = 1 см. Размер экземпляра записывается ещё и в файл комнаты (`realWidthCm/realHeightCm`) — это копия на момент сохранения.

`schema_version: 4` = метры. Старые файлы (px при 640 px/м; радиусы «в px») читаются и пересчитываются автоматически, а при сохранении становятся метрическими. Подробная таблица и формулы для Godot — в `UNITS.md`.

## 4. Разрушение: блоки и объекты

Две разные сущности с разной логикой:

| | Блоки (грунт, стены) | Объекты (кровать, верстак, дверь…) |
|---|---|---|
| Что это | Категория ОС «Блок / материал» (`block`), сетка 1×1 м | Любая другая категория, размер 20…500+ см |
| Как ломаются | **Куском 20×20 см** (5×5 в блоке); состояние блока — маска кусков | **Целиком**, по HP из вкладки «Разрушение» |
| Твёрдость | Твёрдый кусок = красная зона комнаты | Как у объекта: столкновение/физика |
| Постройки | Категория `building` (стены, полы, двери) остаётся на месте (`physics: STATIC`) | Обычные объекты `DYNAMIC` падают вниз до твёрдого и получают урон от высоты и веса — это считает игра |
| Что даёт | `block.drop_table` (шанс зависит от навыка и инструмента) | `destruction.onDestroy` |

Обвалов нет; копать можно везде, в том числе через границу комнаты (скорость ограничит игровая механика). В редакторах блоки ставятся только целыми; частично разрушенные блоки появляются в игре. Внешние углы массива блоков срезаются фаской (только внешний вид). Подробно — в `02-Room-Editor.md` и `UNITS.md`.

## 5. Как ссылаются друг на друга файлы

| Ссылка | Откуда → куда |
|---|---|
| `instances[].objectId` | комната → `data/objects/<id>.json` (по **id внутри файла**, имя файла запасное) |
| `door.toRoom` | дверь в комнате → `data/rooms/<id>.json` |
| `world.blocks[].type` | блок → объект категории «Блок / материал» (`block`) |
| `rooms[].room`, `sequence[].room` | здание → комната |
| слот `RANDOM` / `POOL` | здание → комнаты по типу, роли и лестницам |
| `block.tool`, `block.drop_table[].item` | материал → объекты (инструмент, добыча) |
| `action_settings.*`, `crafting.recipe.pattern` | объект → объекты (инструмент, расход, выдача, ингредиенты) |
| `destruction.damaged.image` / `broken.image` | объект → PNG повреждённого / разрушенного вида |
| `data/categories.json` | ОС → Room Editor (библиотека) и реестр |
| `image` слоя фона | комната: `rooms/<файл>` (от `assets/sprites`); здание: `assets/sprites/rooms/…` (с префиксом) — загрузчики понимают оба |

Битые ссылки проверяет кнопка «🔍 Проверить ссылки проекта» в ОС (объекты, материалы блоков, комнаты и типы блоков в них, персонажи Assembler; здания не проверяет). Полную проверку всего проекта, включая здания, файлы и слоты, делает **Project Registry**.

## 6. Общие соглашения по коду

- **Структура приложения:** `index.html` (разметка + подключения), `css/app.css`, `js/NN-название.js`. Номер = порядок загрузки; **INIT всегда последний**.
- **Без `import`/`export`:** все скрипты делят одну глобальную область — функции и переменные доступны из любого файла. Поэтому имена функций менять нельзя, а `onclick="…"` в HTML работает с глобальными функциями.
- **Главные точки обновления** (вызывать после любого изменения данных):

| Приложение | Функция |
|---|---|
| ОС | `update()` — записывает историю, пересобирает JSON и превью |
| Room Editor | `renderRoom()` + `scheduleHistoryPush()` — перерисовка холста и шаг истории |
| Building Editor | `recomputeAndRender()` — пересчёт позиций, дверей, холста и списка |
| Project Registry | `scanProject()` — скан → связи → проверки → `render()`; после — `render()` |
| Object Plan | `buildModel()` — индексы, связи, волны; `render()` / `rerender()` |

- **Модуль поверх существующих:** в Room Editor модуль 15 подключается **обёртками**: `const __f=f; f=function(){ __f(); … }` — так можно добавить функциональность, не правя чужие файлы. Так же он подключает твёрдость блоков: обёртка над `zoneColorAt`.
- **Ошибки картинок:** любая загрузка картинки с диска при ошибке (нет файла, файл повреждён) должна давать исключение или заглушку, но **не вечное ожидание**.
- **Экранирование:** всё, что попадает в `innerHTML` из данных, — через `esc(...)`.
- **Единицы на границе:** внутри px, в JSON метры; переводить только при сохранении, загрузке и в полях ввода.
- **Категории:** список категорий живёт в коде ОС (`CAT_LABELS` + кнопки) и записывается в `data/categories.json`; Room Editor и реестр читают его и дополняют категориями, найденными у объектов. Id `block` (материалы блоков) зашит в Room Editor и реестре.

## 8. Что сейчас требует внимания

1. **`destruction.enabled` включён по умолчанию у любого объекта**, кроме блоков (у блока он выключен, разрушение по кускам — вкладка «Материал»), поэтому по нему нельзя отличить разрушаемые объекты. Палитра блоков фильтруется по категории `block`.
2. **Блоки не рисуются в превью Building Editor** — в здании видны только фоны и объекты комнат.
3. **Гравитацию и падение объектов считает игра.** Room Editor только подсвечивает объект красным, если он оказался внутри блока; объекты не двигаются при правке грунта.
4. **Окружение 3×3 (`world.neighbors`) удалено.** В старых комнатах ключ остаётся до пересохранения; игре читать его не нужно (реестр помечает такие комнаты как `LEGACY_NEIGHBORS`). Не путать с «ролью комнаты в здании» (сетка 3×3 `TOP_LEFT … BOTTOM_RIGHT`) — она работает как раньше.
5. **Пути фонов** в комнатах и зданиях записаны по-разному (см. раздел 5).
6. В режиме «Улица» (Building Editor) роль слота и лестницы в JSON не пишутся.
7. Размер анимированного существа задаётся как размер **кадра**, а не тела; пропорции берутся из кадра.
8. Комнаты с блоками должны иметь целые размеры и стоять в здании на целом метре — Building Editor привязывает такие комнаты к метру и предупреждает, если сетка сбита.
9. **Размер экземпляра в файле комнаты — снимок.** Если размер объекта изменили в ОС, в уже сохранённых комнатах (их читает игра) остаётся старый. Room Editor при открытии комнаты подставляет актуальный размер из ОС (нужно сохранить комнату), кнопка «📐 Размеры из ОС во всех комнатах» переписывает файлы сразу, Building Editor в превью берёт размер из ОС, а реестр показывает расхождения кодом `INSTANCE_SIZE`.
