# Story Map — справочник

Визуальный конструктор сюжетных узлов и переходов: события, выборы игрока, фоновые (не зависящие от игрока) события, и то, как всё это меняет мир — репутацию фракций, уровень опасности, счётчики дней и любые другие авторские переменные. Узлы группируются по тем же **системам игры**, что уже описаны в Object Plan (`postapocalyptic_survival_master_game_design.md` — оттуда взята вся структура), поэтому граф не превращается в кашу по мере роста. Не редактор игровых данных ОС/Room Editor/Building Editor — отдельный слой, описывающий сюжет и последствия, на основе которого потом пишется код игры и ИИ. Пишет только `data/story.json`. Читает его `story-bot/` (симулятор прохождения, `10-Story-Bot.md`).

Запуск: открыть `story-map/index.html` в Chrome/Edge.

---

## 1. Мировые переменные

Авторский список (левая панель, «Мировые переменные»): `id` (генерируется), название, тип (**число** — счётчик типа репутации или уровня опасности; **флаг** — просто да/нет) и начальное значение. Условия и эффекты узлов/переходов ссылаются только на переменные из этого списка — «Проверки» (см. ниже) ловят ссылки на удалённую или ещё не созданную переменную.

## 2. Подключённые каталоги (Object Plan, Shelter Architecture Map)

Story Map подключает вживую два чужих каталога прямо их же скриптами (как `ipt/image-prep-tool` подключает Object Plan) — правишь их там, здесь сразу видно новое, ничего вручную синхронизировать не нужно:

- **Object Plan** (`../object-plan/js/02-vocab.js` + `03-05-data-*.js`) — даёт список предметов (`PLAN_ITEMS`) для поля «Нужны предметы», список навыков (`OS_SKILLS`) для «Нужны навыки» и список **систем игры** (`SYSTEMS`) — это и есть таксономия «разделов», по которым группируются узлы (см. §3).
- **Shelter Architecture Map** — только его каталог систем (`../Shelter-Architecture-Map/js/03…06-data-systems-*.js`), **без** его `02-vocab.js` (там `const PRIORITIES`/`STATUSES` совпадают по именам с Object Plan — загрузка обоих `02-vocab.js` сразу дала бы `SyntaxError`). Вместо этого Story Map сам объявляет `addSystems()`/`SAM_SYSTEM_ITEMS` перед этими файлами — получается тот же список Godot-систем, что видит сам Shelter Architecture Map, только на чтение. Это необязательное поле узла «Система Godot» — обратной связи пока нет: Shelter Architecture Map не читает `data/story.json` (можно добавить позже).

## 3. Узлы

Три вида (влияют только на цвет рамки и подсказки по умолчанию — структура одна и та же): **Событие**, **Выбор** (явное решение игрока), **Фоновое** (срабатывает по таймеру независимо от игрока).

Отдельно от вида — **раздел** (`category`, выпадающий список из `SYSTEMS` Object Plan: вода, энергия, фракции, крафт, ИИ-автономность и т. д.) и **доп. теги** (`tags` — тот же список, можно несколько) — это то, по чему узлы группируются в левой панели (см. §6) и по чему автоматически подключаются импортированные идеи (см. §7). Раздел — один главный, теги — все остальные системы, которых узел тоже касается.

У каждого узла: название, текст (что видит игрок), **когда доступен**:
- **▶ Старт** — доступен сразу, с него начинается игра (должен быть ровно один такой узел — иначе «Проверки» пожалуются).
- **⚑ По условиям** — список условий (переменная / знак `≥ ≤ = ≠ > <` / число), все должны выполняться.
- **⏱ Фоновое, по таймеру** — срабатывает само через N игровых часов после старта игры или после того, как сработал другой указанный узел; можно включить «повторять».

**Что меняет при срабатывании** — список эффектов (переменная / `= + −` / число).

**Параметры для бота-симулятора**: длительность в игровых часах, шанс опасности (0…1), расход еды/воды (**отрицательное число — восполняет**, например «поесть»), **нужны предметы** / **нужны навыки** — фишки с автодополнением, значения берутся из `PLAN_ITEMS`/`OS_SKILLS` (см. §2): начни печатать название в поле рядом — подставится из списка; если совпадения нет, фишка всё равно добавится как есть (не блокирует ввод).

**Концовка** — если заполнено (например `death`, `victory`, своя строка), узел считается финалом.

## 4. Переходы (связи)

Два способа создать: **потянуть за кружок** на правом краю узла на холсте до другого узла (перетаскивание пустого места холста — панорама; колёсико — масштаб), или кнопкой «+ добавить переход» в инспекторе. У каждого перехода — текст, целевой узел, свои «Требуется» и «Меняет» (в дополнение к узловым).

## 5. Проверки

| Проблема | Смысл |
|---|---|
| Нет стартового узла | Ни один узел не отмечен «▶ Старт» |
| Ссылается на несуществующую переменную | Условие/эффект использует id переменной, которой нет в списке |
| Переход ведёт в несуществующий узел | `target` перехода не совпадает ни с одним id узла |
| Отсчёт таймера от несуществующего узла | `sinceNode` фонового узла не существует |
| Тупик без развития (info) | У узла нет ни переходов, ни отметки концовки |
| Недостижим (info) | Ни один переход и ни одно стартовое/фоновое событие не ведёт на этот узел |

## 6. Левая панель: узлы по разделам

Список узлов сгруппирован по `category`: заголовок раздела (название системы + сколько в нём узлов), под ним — узлы этого раздела, каждый с одной строкой «→ на что влияет» (имена переменных из его собственных эффектов и эффектов его переходов). Клик по узлу открывает его в инспекторе **и** переносит холст так, чтобы узел оказался по центру экрана (масштаб сбрасывается на 100%) — это и есть «зашёл в раздел → увидел ветки → кликнул → перешёл в неё».

## 7. Импорт идей — универсальный JSON-шаблон

Одна идея — самостоятельный кусок сюжета в отдельном JSON-файле: свои узлы (с **локальными** `ref` вместо настоящих id — они одноразовые, только чтобы сослаться друг на друга внутри этого же файла), свои новые переменные и явные **links** — с какими уже существующими узлами (по разделу или тегу) новые узлы должны связаться. Кнопки в левой панели («Импорт идей»): «⬇ Шаблон идеи» скачивает рабочий пример (ровно про то, что ты описывал — NPC сам подсказывает донести аккумулятор), «📥 Импорт идеи (JSON)» — открывает файл и добавляет его в граф.

Импорт **только добавляет**: переменные с уже существующим id пропускаются (не перезаписываются), узлы никогда не удаляются, а `links` ищутся по **текущему**, уже пополненному списку узлов — поэтому если сегодня ты импортируешь идею про фракции, а завтра другую идею, тоже помеченную тегом `factions`, она сама подключится и к старым узлам, и к тем, что добавила первая идея. Это не «ИИ понимает смысл» — это прямое совпадение по `match_category`/`match_tag`, которые сам указываешь в файле; надёжно и предсказуемо, зато не обещает большего, чем может.

Формат файла:

```jsonc
{
  "idea_id": "npc_self_hint_example",           // просто метка для журнала импортов
  "title": "NPC сам подсказывает, чего не хватает",
  "variables": [                                 // новые мировые переменные (пропускаются, если id уже есть)
    {"id":"v_electricity_home","name":"Электричество в доме","type":"flag","start":0,"min":0,"max":1}
  ],
  "nodes": [
    {
      "ref": "n1",                               // локальная ссылка, только для этого файла
      "title": "NPC: намёк про свет",
      "text": "«Темновато тут. Если бы был аккумулятор — я бы свет наладил.»",
      "type": "background", "category": "ai", "tags": ["energy","story"],
      "trigger": {"kind":"scheduled","afterHours":24,"sinceNode":"","repeat":true},
      "effects": [],
      "sim": {"durationHours":0,"dangerChance":0,"foodCost":0,"waterCost":0,"requiresItems":[],"requiresSkills":[]},
      "ending": "",
      "choices": [
        {"label":"Занести аккумулятор","target_ref":"n2","requires":[],
         "effects":[{"var":"v_electricity_home","op":"set","value":1}],"sim":{"requiresItems":["battery_cell"]}}
      ]
    },
    {"ref":"n2","title":"Свет в доме включён","text":"NPC радуется.",
     "type":"event","category":"energy","tags":["ai"],
     "trigger":{"kind":"conditions","all":[]},"effects":[],"sim":{},"ending":"","choices":[]}
  ],
  "links": [
    // от узла n2 — ко ВСЕМ текущим узлам с тегом "energy" (кроме себя), в обе идеи-импорта одинаково
    {"from_ref":"n2","match_tag":"energy","label":"(связано: тоже про энергию)"}
    // или "match_category":"energy" вместо match_tag — тогда сравнивается основной раздел узла, а не доп. теги
  ]
}
```

`target_ref` внутри `choices` ссылается на `ref` из этого же файла (превращается в настоящий id при импорте); можно вместо этого указать `target` с настоящим id уже существующего узла напрямую, если он тебе известен. Узлы новой идеи размещаются на холсте ниже уже существующего содержимого, чтобы не накладывались друг на друга — их несложно перетащить туда, куда нужно, после импорта.

## 8. Хранение и формат

Пишет только `data/story.json`: `{schema_version, variables:[{id,name,type,start,min,max}], nodes:[{id,title,text,type,category,tags,samSystem,x,y,trigger,effects,sim,choices,ending}]}`, где `sim.requiresItems`/`sim.requiresSkills` — массивы id (а не текст). Файлы, сохранённые до этого раздела (без `category`/`tags`/массивов requires), читаются как раньше — при загрузке подставляется `category:'story'`, `tags:[]`, а старый текст через запятую в requires разбирается в массив. `Ctrl+Z`/`Ctrl+Shift+Z` — отмена/возврат (история правок графа в браузере, не файла на диске; сама отмена ставит счётчик идей-импортов, но не может отменить уже случившийся `fetch`/выбор файла — только его результат в графе).
