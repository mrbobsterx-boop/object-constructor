# Project Registry — справочник

**Регистр всего проекта**: читает ту же папку проекта, что и редакторы, и показывает, что в ней есть (объекты, блоки-материалы, комнаты, здания, наборы, персонажи Assembler, картинки и звуки), кто на кого ссылается и что сломано. Реестр **только читает** — в проекте он ничего не меняет.

- Файл запуска: `index.html` (двойным кликом, `file://`; нужен Chrome/Edge — File System Access API).
- Скрипты — обычные `<script>` с **общей глобальной областью видимости** (без `import`/`export`); номер файла = порядок загрузки; `11-init.js` — всегда последним.
- Папка подключается кнопкой «📁 Подключить папку проекта» (та же, что в редакторах; дескриптор запоминается в IndexedDB `project_registry_fs`). «🔄 Сканировать проект» перечитывает всё заново — после правок в редакторах нажми её.

## 1. Разделы

| Раздел | Что показывает |
|---|---|
| **Обзор** | Счётчики, «здоровье проекта» (ошибки / предупреждения / инфо), объекты по категориям, типы комнат, настройки и служебные файлы |
| **Объекты** | Все `data/objects`: категория, игровой размер, размещение/физика, группа, где стоят, сколько ссылок. Фильтры: категория, группа, «с проблемами / нигде не используются / разрушаемые / крафт / без размера». Карточка: поля, «использует», «где используется», файлы, проблемы |
| **Блоки и материалы** | Объекты категории `block`: твёрдость, инструмент, срез угла, таблица добычи, где блоки стоят в комнатах |
| **Комнаты** | Все `data/rooms`: тип, размер, роль/лестницы, объекты, блоки, двери, в каких зданиях стоит. Карточка: состав, двери (куда ведут), блоки по типам, где используется |
| **Здания** | Все `data/buildings` (здание и улица): состав, этажи, случайные слоты, фоны. Карточка: таблица комнат с позицией, обрезкой, размером и проверкой сетки блоков |
| **Наборы** | `data/sets` — служебные заготовки Room Editor |
| **Персонажи (Assembler)** | `data/characters`, `data/rigs`, `data/parts`: слои, части, какие объекты ОС связаны с персонажем |
| **Файлы** | Картинки и звуки; кто на них ссылается; «без ссылок» |
| **Справочники** | Категории ОС, типы комнат, группы взаимозаменяемости, теги; клик по строке открывает список с этим фильтром |
| **Неиспользуемое** | Объекты и комнаты, которые нигде не встречаются, и файлы без ссылок |
| **Проблемы** | Все находки проверок; фильтры по уровню, месту и коду |

Клик по строке открывает карточку; ссылки внутри карточек ведут дальше, «← Назад» возвращает. Переход из меню сбрасывает поиск и фильтры.

## 2. Данные

**Читает (только чтение):**

| Путь | Что |
|---|---|
| `data/objects/*.json` | объекты ОС (`schema_version 4`) |
| `data/rooms/*.json` | комнаты Room Editor |
| `data/buildings/*.json` | здания и улицы Building Editor |
| `data/sets/*.json` | наборы Room Editor |
| `data/characters/`, `data/rigs/`, `data/parts/<риг>/<слот>/` | Character Assembler |
| `data/categories.json` | категории ОС — пишет ОС при подключении папки и при сохранении |
| `data/project_settings.json`, `data/room_recipes.json` | настройки проекта и рецепты комнат (Room Editor) |
| `assets/sprites/**`, `assets/sounds/**` | список картинок и звуков; картинки объектов — для миниатюр |

Единицы те же, что в редакторах (`UNITS.md`): в JSON — метры, размер объекта — сантиметры; старые файлы (px при 640 px/м) пересчитываются при чтении и помечаются `LEGACY_UNITS`.

### Ссылки, которые отслеживает реестр

| Ссылка | Откуда → куда |
|---|---|
| `instances[].objectId` | комната → объект |
| `instances[].door.toRoom` | дверь → комната |
| `world.blocks[].type` | блок в комнате → объект (категория `block`) |
| `rooms[].room`, `sequence[].room` | здание → комната |
| слот (`RANDOM` / `POOL`) | здание → комнаты по типу, роли и лестницам |
| `action_settings.*.tool / consume.item / produce.item` | объект → объекты |
| `crafting.recipe.pattern[].id` | объект → ингредиенты |
| `block.tool`, `block.drop_table[].item` | материал → инструмент и добыча |
| `character_ref.id` | объект → персонаж Assembler |
| `appearance.asset`, `visuals.*`, `destruction.*`, `recipeImage`, фоны комнат и зданий | → файлы в `assets/sprites`; звуки анимаций → `assets/sounds` |

## 3. Проверки

Уровни: **err** — сломанная ссылка или нечитаемый файл; **warn** — вероятная ошибка данных; **info** — к сведению.

| Где | Код | Уровень | Что проверяется |
|---|---|---|---|
| файл | `JSON_BROKEN` | err | JSON не читается |
| все | `ID_DUP` | err | одинаковый id в двух файлах |
| все | `ID_FILE` / `ID_SLUG` | warn | имя файла ≠ id; недопустимые символы в id |
| все | `LEGACY_UNITS` | info | `schema_version < 4` |
| объект | `NO_CATEGORY` / `CATEGORY_UNKNOWN` | err / warn | нет категории; категории нет в `categories.json` |
| объект | `NO_SIZE` / `SIZE_STEP` / `SIZE_ASPECT` | warn / info / warn | нет игрового размера; размер не целое число см; размер не совпадает с пропорциями картинки (картинка растянута) |
| объект | `NO_IMAGE` / `ASSET_MISSING` / `SOUND_MISSING` | warn / err\|warn / warn | нет картинки; файл не найден (основная картинка — err) |
| объект | `REF_MISSING` | err | инструмент, расход, выдача, ингредиент, добыча, персонаж не найдены |
| объект | `ROOM_TYPE_UNKNOWN` | info | разрешённого типа комнаты ни у одной комнаты нет |
| материал | `BLOCK_SIZE` / `BLOCK_PHYSICS` / `BLOCK_HARDNESS` / `BLOCK_DROP` / `BLOCK_NO_DROPS` / `BLOCK_NO_DATA` | warn / info | не 100×100 см, физика не STATIC, твёрдость 0, шанс вне 0…1 или min>max, пустая добыча |
| комната | `OBJECT_MISSING` / `NO_OBJECT_ID` | err / warn | объект не найден / экземпляр без objectId |
| комната | `INSTANCE_SIZE` | warn | размер экземпляра в файле комнаты отличается от размера объекта в ОС (лечится кнопкой «Размеры из ОС во всех комнатах» в Room Editor) |
| комната | `DOOR_TARGET` / `DOOR_NO_TARGET` / `DOOR_SELF` | err / warn | дверь в несуществующую комнату / никуда / в себя |
| комната | `BLOCK_TYPE_MISSING` / `BLOCK_TYPE_CATEGORY` | err / warn | тип блока не найден / не категории `block` |
| комната | `BLOCK_OUTSIDE` / `BLOCK_ROOM_SIZE` | warn | блоки за границей; размер комнаты с блоками не кратен 1 м |
| комната | `NO_TYPE`, `BG_MISSING` | warn | нет типа; фон не найден |
| комната | `LEGACY_BLOCK_STATE` / `LEGACY_NEIGHBORS` | info | блоки со `state`; ключ `world.neighbors` (окружение 3×3 больше не используется) |
| здание | `ROOM_MISSING` / `ROOM_EMPTY` | err | комната не найдена / не указана |
| здание | `SLOT_NO_MATCH` / `SLOT_NO_TYPE` | warn | слот или пул без подходящих комнат / без типа |
| здание | `OVERLAP` | warn | комнаты одного этажа пересекаются (допуск 1 см; обрезка учитывается) |
| здание | `BLOCK_GRID` | warn | комната с блоками стоит не на целом метре (для «Здания» — с учётом обрезки слева/сверху, для «Улицы» — по накопленной ширине) |
| здание | `DOORLINK_BROKEN` | err | связь дверей на несуществующую комнату-экземпляр или дверь |
| набор | `OBJECT_MISSING` | err | объект набора не найден |
| персонаж | `RIG_MISSING` / `PART_MISSING` | err | риг или часть не найдены |
| проект | `DIR_MISSING`, `NO_CATEGORIES_FILE`, `NO_SETTINGS` | err / warn / info | нет папок; нет служебных файлов |
| проект | `RECIPE_TYPE` / `RECIPE_GROUP` / `RECIPE_RANGE` | info / warn | рецепты комнат: нет комнат такого типа / нет объектов в группе / «от» больше «до» |
| проект | `FILE_ORPHANS` | info | файлы, пути которых не встречаются ни в одном JSON (список — в «Файлы») |

**Неиспользуемое.** Объект «используется», если он стоит в комнате или наборе, лежит как тип блока или на него ссылается другой объект. Комната — если она стоит в здании, является целью двери или может быть выбрана слотом. Игровая логика (спавн персонажей, предметы из добычи) реестру неизвестна — часть «неиспользуемого» может быть нужна игре.

## 4. Скрипты (модули)

| Файл | За что отвечает |
|---|---|
| `01-core-utils.js` | Хелперы (`esc`, `fmt`, `normPath`), единицы (`lenM`), папка проекта (File System Access + IndexedDB), чтение JSON и файлов |
| `02-scan.js` | `scanProject()` — читает все источники в `registry` (объекты, комнаты, здания, наборы, Assembler, файлы, настройки) |
| `03-relations.js` | Индексы `idx`, связи «использует / используется в», справочники `dict`, ссылки на файлы `fileRefs` |
| `04-checks.js` | `runChecks()` — все проверки; `problemsOf`, `problemCounts`, `orphanFiles` |
| `05-ui-core.js` | Навигация, разметка (`lnk`, `card`, `kv`, `table`), список с фильтрами `listView`, миниатюры, делегирование кликов |
| `06-view-overview.js` … `10-view-other.js` | Разделы (`VIEW_RENDERERS`) и карточки (`ENTITY_RENDERERS`) |
| `11-init.js` | Кнопки, первая отрисовка, восстановление папки (**всегда последним**) |

Главные глобальные переменные: `registry` (результат скана), `idx` (карты по id), `dict` (справочники), `fileRefs`, `problemIndex`, `ui` (текущий раздел, карточка, стек «Назад», фильтры).

## 5. Известные особенности

- Реестр не знает формата картинок Character Assembler: файл, упомянутый только в его JSON по нестандартному пути, может попасть в «без ссылок».
- Скан читает все JSON проекта; в очень больших проектах он занимает несколько секунд. Миниатюры подгружаются после скана в фоне.
- Список в таблицах ограничен 500 строками (300 для проблем) — уточняй поиском.
- `RANDOM`-слот здания хранит в файле id комнаты, выбранной при редактировании; реестр проверяет и условие слота, и эту комнату (если она пропала — только предупреждение).
