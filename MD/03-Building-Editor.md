# Building Editor — справочник

Редактор **зданий и улиц**. Собирает из готовых комнат (Room Editor) план здания или цепочку «улица» и сохраняет его в `data/buildings/<id>.json`, который читает игра (Godot).

- Файл запуска: `index.html` (открывается двойным кликом, `file://`; нужен Chrome/Edge — используется File System Access API).
- Порядок подключения скриптов в `index.html` менять нельзя: скрипты — обычные `<script>` с общей глобальной областью видимости (без `import`/`export`), номер файла = порядок загрузки. `10-init.js` всегда последний.

## 1. Что умеет редактор

### Два режима (выпадающий список «Режим» в шапке)

| Режим | Что это | Как размещаются комнаты |
|---|---|---|
| **BUILDING — Здание** | 2D-план с этажами и дверями | Свободное перетаскивание мышью, привязка к сетке 10 см и к краям соседей (**комнаты с блоками — только на целый метр**); двери соседних комнат автоматически соединяются |
| **STREET — Улица** | цепочка комнат встык, без дверей | Комнаты идут подряд по порядку списка, выровнены по низу («уровень земли»); перетаскивания нет, порядок меняется кнопками ▲▼ |

### Комнаты
- **Каталог комнат** (слева) — все `data/rooms/*.json` из папки проекта. Клик по комнате добавляет её в план (режим FIXED). Комнаты с разрушаемыми блоками помечены «блоки (сетка 1 м)», а если их размер не кратен 1 м — «⚠ размер не кратен 1 м».
- **Случайный слот** (RANDOM) — не конкретная комната, а условие: тип комнаты + роль в композиции (3×3: `TOP_LEFT … BOTTOM_RIGHT`) + обязательные лестницы. Редактор подбирает подходящую комнату случайно (кнопка 🎲 перевыбирает). В файл слот уходит как условие, а не как выбранная комната.
- **Этаж** выбранной комнаты (целое число: 0 — основной, +1/+2 — выше, −1/−2 — подземелье). Пересечения проверяются и привязка к краям работает только между комнатами одного этажа.
- **Обрезка** выбранной комнаты (слева/справа/сверху/снизу, в метрах) — обрезается только экземпляр комнаты в здании, исходный файл комнаты не меняется.
- **Фоны здания** — несколько картинок-слоёв (фасад, небо…), относящихся к зданию, а не к комнате. Источник: файл из `assets/sprites/rooms`, «Выбрать файл», «Вставить» из буфера или Ctrl+V. Настраиваются X/Y (м), масштаб, прозрачность, поворот, flip H/V, слой (z). Мышью — перетаскивание и изменение размера за угловые ручки.
- **Превью комнат** на плане — настоящие фоны и объекты комнаты (читаются с диска один раз на комнату). Если что-то не удалось показать, на комнате появляется значок «⚠ N» с перечнем причин. Объект без картинки рисуется пунктирной рамкой его размера.
- **Проверка размещения**: красная рамка = слот без подобранной комнаты (`MISSING_ROOM`), выход за границы холста (`OUTSIDE`), пересечение с другой комнатой того же этажа (`OVERLAP`), комната с блоками не на целом метре (`BLOCK_GRID`). Ошибка не блокирует работу, но при сохранении в режиме «Здание» редактор просит подтвердить.
- **Комнаты с блоками и сетка 1 м.** Блоки лежат на сетке 1×1 м от левого верхнего угла комнаты. Чтобы сетки соседних комнат совпали (яма и грунт стыкуются без сдвига), комната с блоками при перетаскивании привязывается к **целому метру** (после притяжения к краям); начало сетки считается с учётом обрезки: `x − обрезка слева` и `y − обрезка сверху` должны быть целыми. Новая комната или случайный слот с блоками сразу встаёт на (1 м; 1 м). Если позиция всё же не на метре (файл открыт из старой версии или комната перевыбрана слотом), рамка красная, а при сохранении — предупреждение. Размеры такой комнаты должны быть целыми метрами, иначе привязка к метру собьёт стык с соседом с дробной шириной (лечится размером комнаты в Room Editor). **Сами блоки в превью здания не рисуются** — видны только фоны и объекты.
- **Масштаб и навигация**: кнопки −/+/1:1/«Вписать», колесо мыши (с сохранением точки под курсором), панорамирование правой кнопкой мыши. Сетка «1 м» (мелкая) и «10 м» (крупная) включается флажком.

### Единицы
Все длины в JSON — **метры**. Внутри редактора координаты в пикселях (`100 px = 1 м`), перевод — в модуле 01 (`pxToM`/`mToPx`). Старые файлы (px при 640 px/м) читаются и пересчитываются сами.

## 2. Данные

**Читает** (из подключённой папки проекта):

| Путь | Зачем |
|---|---|
| `data/rooms/*.json` | каталог комнат, размеры, двери, роль, лестницы; превью |
| `data/objects/*.json` | превью объектов (размер и картинки) |
| `assets/sprites/…` | картинки фонов комнат, объектов, фонов здания |
| `data/buildings/*.json` | открытие сохранённого здания |

**Пишет:**

| Путь | Когда |
|---|---|
| `data/buildings/<id>.json` | «💾 Сохранить здание» |
| `assets/sprites/rooms/building_backgrounds/<имя>` | при добавлении фона из файла/буфера (копия картинки кладётся в проект) |

### Формат `data/buildings/<id>.json` (`schema_version: 4`)

Режим **BUILDING**:
```json
{
  "schema_version": 4, "id": "house_01", "name": "Дом", "layout_mode": "BUILDING",
  "rooms": [ { "instance_id":"place_…", "order":0, "room":"hall", "x_m":0, "y_m":0, "floor":0,
               "mode":"FIXED", "type_filter":null, "required_role":null, "required_stairs":[],
               "crop_m":{"left":0,"right":0,"top":0,"bottom":0} } ],
  "backgroundLayers": [ { "image":"assets/sprites/rooms/…png", "x_m":10, "y_m":6, "width_m":10, "height_m":6,
                          "opacity":1, "rotation":0, "flipH":false, "flipV":false, "z":0 } ],
  "door_links": [ { "a":{"room_instance":"…","door_index":0}, "b":{"room_instance":"…","door_index":1} } ]
}
```
Режим **STREET**: вместо `rooms` — `sequence`: элементы `{"type":"FIXED","room":"id"}` и `{"type":"POOL","type_filter":"kitchen","count":3,"randomize_each_playthrough":true}` (подряд идущие RANDOM-слоты одного типа сворачиваются в один пул с количеством). В режиме «Улица» фильтры роли и лестниц в файл **не пишутся**.

`x_m/y_m` комнаты — левый верхний угол в метрах; у фона `x_m/y_m` — **центр**, размер — реальный (`width_m/height_m`), масштаб восстанавливается как `width_m·100 / ширина_картинки_px`.

> Замечание: путь фона здания записан как `assets/sprites/rooms/…`, а в комнатах путь фона — `rooms/…` (от `assets/sprites`). Загрузчик понимает оба, игре тоже нужно.

| `04-placed-rooms.js` | Состояние здания (размещённые комнаты, режим, выбранное), фильтры слота (роль/лестницы), добавление/перемешивание/удаление комнат, подбор комнаты в случайный слот |

## 4. Справочник функций

### 01-core-utils.js — утилиты, единицы, папка проекта

| Функция | Что должна делать |
|---|---|
| `sanitizeSlug(s)` | Превращает строку в безопасный идентификатор: нижний регистр, только `a-z0-9_-`, остальное → `_`, без `_` по краям. Используется для id здания и имён файлов |
| `translit(str)` | Транслитерирует кириллицу в латиницу и чистит результат до slug — автоматический id из названия здания |
| `esc(s)` | Экранирует `& < > " '` — обязательна при вставке имён в `innerHTML` |
| `pxToM(px, digits=2)` | px редактора → метры, округление до сантиметра (или до `digits` знаков) |
| `mToPx(m)` | Метры → px; округляет до 0,001 px, чтобы убрать шум вида `6.4*100 = 640.0000000000001` |
| `lenPx(o, mKeys, legacyKey, fallbackPx, legacyPPM)` | Читает длину из JSON: сначала ключ в метрах (`mKeys`, строка или массив), иначе старый ключ в px (делит на 640, если не указано иное), иначе `fallbackPx` |
| `bgScaleFromJSON(l, nativeW, widthKey)` | Масштаб фона: `width_m·100/nativeW`; для старых файлов — `scale·100/640` |
| `roomFromJSON(d)` | Приводит JSON комнаты (новый или старый) к единому виду в px: размеры, координаты слоёв фона и объектов |
| `idbOpen()` / `idbSet(key,val)` / `idbGet(key)` | Хранилище IndexedDB (`building_editor_fs`) для запоминания дескриптора папки проекта между запусками |
| `getSubdir(root, pathStr, create)` | Проходит по пути `a/b/c` вглубь папок; при `create=true` создаёт недостающие |
| `writeFileToProject(relPath, bytes)` | Пишет файл по относительному пути в папку проекта (создаёт папки); возвращает `false`, если папка не подключена |
| `updateFolderStatus(needsRegrant)` | Показывает состояние папки в шапке; кнопка «Разрешить доступ» видна, если нужно подтвердить права |
| `connectProjectFolder()` | Диалог выбора папки (только Chrome/Edge), сохранение дескриптора, загрузка каталога комнат и списка зданий |
| `tryRestoreProjectFolder()` | При старте достаёт сохранённый дескриптор; если права уже даны — сразу загружает данные, иначе просит «Разрешить доступ» |
| `regrantProjectFolder()` | Запрашивает права заново по кнопке и перечитывает данные |

|---|---|

Двери = экземпляры объектов с `door` в комнате. Сбрасывает кэши превью и индекса объектов. Битые файлы пропускает с предупреждением в консоль |

### 04-placed-rooms.js — состояние здания и слоты

Состояние: `placedRooms[]` (`instanceId, mode, roomId, typeFilter, requiredRole, requiredStairs, floor, crop, x, y, w, h, name`), `selectedPlacedId`, `buildingMode`, `buildingBackgrounds[]`, `selectedBuildingBgId`; константа `GRID_SNAP` = 10 см в px.

| Функция | Что должна делать |
|---|---|
| `addPlacedRoom(roomId)` | Добавляет комнату из каталога как FIXED в позицию (20, 20) — комнату с блоками в (100, 100), то есть на целый метр — выбирает её, перерисовывает |
| `roomMatchesRandomSlot(r, entry)` | Подходит ли комната слоту: совпадает тип; если задана роль — совпадает роль; все требуемые лестницы есть у комнаты |
| *(кнопка «+ Добавить слот»)* | Создаёт слот, подбирает комнату; если выбранная комната с блоками — ставит слот на (100, 100) |
| `rerollRandomSlot(entry)` | Выбирает случайную подходящую комнату в слот (сбрасывает обрезку, задаёт размер и имя `🎲 …`). Если подходящих нет — слот остаётся пустым (`roomId=null`, размер 6,4×2,2 м, имя «нет подходящих комнат») |
| *обработчики* | Смена режима (перерисовка, показ «Перемешать»); «🎲 Перемешать всё» (тасует только RANDOM-слоты, FIXED остаются на своих индексах); «+ Добавить слот» (тип, роль, лестницы, этаж из формы); «Применить» этаж; «✕ Удалить выбранную» |

### 05-room-visuals-doors.js — превью и двери

| Функция | Что должна делать |
|---|---|
| `getRoomMeta(roomId)` | Возвращает запись комнаты из каталога |
| `loadImageDataUrl(spritesDir, relPath)` | Читает картинку как data URL; путь от `assets/sprites` (префикс `assets/sprites/` допустим). **Любая ошибка — исключение**, а не вечное ожидание |
| `getImageDims(dataUrl)` | Размеры картинки; битый файл — исключение |
| `tryLoadImage(spritesDir, rel)` | Обёртка: `{url, kind}`, где `kind` = `ok` / `missing` (нет файла) / `invalid` (не картинка) |
| `firstFrameFromSheet(dataUrl, frameCount)` | Вырезает первый кадр из листа анимации (полоска равных кадров; если число кадров неизвестно — по отношению ширины к высоте) |
| `loadObjectImage(spritesDir, obj)` | Картинка объекта по цепочке: основная → статичное состояние → первый кадр анимации (idle, иначе первая). Возвращает `{url, problem, path}` |
| `getObjectIndex()` | Один раз читает `data/objects/*.json` и строит индекс по `id` внутри файла (имя файла — запасной ключ, т.к. оно может не совпадать с id) |
| `loadRoomVisual(roomId)` | Загружает превью комнаты в кэш: годные слои фона + все объекты (у которых нет картинки — рамка реального размера) + список `issues`. Ошибки отдельных картинок не прерывают загрузку. В конце перерисовывает холст Размер объекта в превью: актуальный из ОС (`real_width_cm/real_height_cm`) → записанный в комнате → размер картинки (1 px = 1 см) → 10 см |
| `recomputeDoorLinks()` | Пересчитывает `doorLinks`: пары дверей разных комнат ближе `DOOR_LINK_THRESHOLD` (30 см) соединяются, каждая дверь — не более одной пары. В режиме «Улица» связей нет |
| `isDoorLinked(instanceId, doorIdx)` | Соединена ли дверь (зелёная/оранжевая точка на плане) |

### 06-building-canvas.js — холст

| Функция | Что должна делать |
|---|---|
| `recomputeLinearPositions()` | Режим «Улица»: `x` = сумма ширин предыдущих, `y` = так, чтобы низы всех комнат лежали на одной линии |
| `renderBuildingCanvas()` | Полная перерисовка: фоны здания (по z), затем для каждой комнаты — рамка, подпись `название · этаж`, превью (фон, объекты с учётом обрезки), значок ⚠, точки дверей (только «Здание»). Запускает `loadRoomVisual`, если превью ещё нет |
| `snapRoomToEdges(p, nx, ny)` | Притягивает край перетаскиваемой комнаты к краям комнат **того же этажа** в пределах `EDGE_SNAP` (50 см): стык лево/право, верх/низ и выравнивание параллельных краёв |
| `roomHasBlocks(p)` / `snapBlockRoomToMeter(p, nx, ny)` / `isBlockGridAligned(p)` | В комнате есть блоки / позиция, при которой сетка блоков (с учётом обрезки слева/сверху) лежит на целом метре и комната не левее/выше нуля / стоит ли комната на метре (допуск 0,5 см) |
| `startDragPlacedRoom(e, p)` | Перетаскивание: сдвиг с учётом масштаба → сетка 10 см → притяжение к краям → для комнат с блоками привязка к метру → не левее/выше нуля; каждый шаг перерисовывает |
| `rectsOverlap(a, b)` | Пересечение прямоугольников с допуском 1 px (касание не считается) |
| `getBuildingPlacementIssues(p)` | Список проблем комнаты: `MISSING_ROOM`, `OUTSIDE`, `OVERLAP` (только тот же этаж), `BLOCK_GRID` (комната с блоками не на целом метре) |
| `getBuildingPlacementValid(p)` | `true`, если проблем нет |
| `updateBuildingCanvasSize()` | Размер холста: не меньше 20×12 м и с запасом 4 м за крайней комнатой |

### 07-building-backgrounds.js — фоны и обрезка

| Функция | Что должна делать |
|---|---|
| `newBuildingBgPlacement(nativeW)` | Начальные положение и масштаб нового фона: вписать по ширине здания (правый край крайней комнаты, но не уже 10 м), центр по X |

## 5. Как связаны действия (типичный сценарий)

1. Подключить папку проекта → загружается каталог комнат и список зданий.
2. Добавить комнаты кликом в каталоге или слоты «случайная комната».
3. Расставить мышью (Здание) или порядком ▲▼ (Улица); двери стыкуются сами.
4. Добавить фон здания, при необходимости обрезать комнаты.
5. «💾 Сохранить здание» → `data/buildings/<id>.json`.

## 6. Известные особенности

- `addBuildingBackground()` объявлена дважды (см. выше).
- В режиме «Улица» роль слота и требуемые лестницы не сохраняются — только тип и количество.
- Превью читает комнаты и объекты один раз за сессию; после правки комнаты в Room Editor нажмите «🔄 Обновить список».
- Блоки комнат в превью здания **не рисуются**.
- Привязка комнат с блоками к метру перебивает притяжение к краям: рядом с комнатой дробной ширины (например 6,4 м) возможен зазор или наложение — размеры комнат с блоками делают кратными 1 м.
- Проверку всего здания (слоты без комнат, связи дверей, пересечения, файлы фонов) делает Project Registry.
- `image-rendering: pixelated` в превью означает, что крупные картинки при уменьшении выглядят «зубчатыми».
- Размеры объектов в превью берутся из ОС, а не из файла комнаты: игра читает размер из файла комнаты, поэтому после смены размера в ОС нажми в Room Editor «📐 Размеры из ОС во всех комнатах».
