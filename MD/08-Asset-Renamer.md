# Asset Renamer — справочник

Приложение для массового разбора и переименования сырых картинок объектов (например, набранных заранее пачками по 900+ штук) перед тем, как они попадут в `assets/refs/`. Три колонки: **источник** (папка с исходными файлами — только читается и из неё после переноса удаляются обработанные файлы), **редактирование** (раздел/объект/вариация + состояние idle/broken/icon), **назначение** (папка, куда переносятся файлы под итоговым именем). Игровых данных не создаёт — просто готовит правильно названные PNG для `assets/refs/`, которые потом видит Object Plan (см. `05-Object-Plan.md`, `refStateThumbs()` в `07-store.js`).

Запуск: открыть `asset-renamer/index.html` в Chrome/Edge. Источник и назначение — это две **разные, независимо подключаемые** папки (обычно назначение — это `assets/refs/` в папке проекта, а источник — отдельная папка со свежими фотографиями/скринами).

---

## 1. Как автор называет исходные файлы

Типичный рабочий паттерн: один и тот же предмет фотографируется/рисуется в нескольких видах — **1 — хороший, 2 — сломанный/повреждённый, 3 — миниатюра-иконка** для инвентаря, — и все три сохраняются под одним именем с порядковым номером: `chair_wood_kreslo.png`, `chair_wood_kreslo_2.png`, `chair_wood_kreslo_3.png`. Если позже встречается похожий, но другой предмет под тем же именем, нумерация просто продолжается (`_4`, `_5`, `_6`). Иногда «сломанного» вида нет вовсе, и файлы идут подряд без выраженной пары «хороший/плохой». Заранее разложить это по правильным именам руками на 900+ файлах нереально — этим и занимается Asset Renamer.

## 2. Группировка (левая колонка)

Имя файла (без номера в конце) разбирается на три уровня по подчёркиваниям — это только **подсказка**, любое поле можно поправить руками:

| Уровень | Из чего берётся | Насколько чёткий разделитель |
|---|---|---|
| Раздел | 1-й токен | Самый чёткий — смена раздела всегда рисует новую цветную полосу |
| Объект | средние токены | Менее чёткий — просто подзаголовок внутри раздела |
| Вариация | последний токен | Самый нечёткий — это и есть «семья» файлов |
| Номер в конце (`_2`, `_3`…) | — | Группировку вообще не рвёт: все файлы с одним и тем же именем (кроме номера) — одна «семья», показываются вместе одной карточкой |

Каждый раздел получает свой цвет (по хэшу названия) — по цветным блокам сразу видно, сколько одинаковых объектов набралось. Если разбор ошибся (например, восемь файлов `lightbulb_nakalivaniya_1…8` на самом деле восемь *разных* ламп, а не хороший/плохой/иконка одной) — это решает пользователь глазами по крупным превью, а не автоматика.

## 3. Выбор и правка (Ctrl+клик)

- **Клик по файлу** — выбирает всю его семью целиком (карточка сдвигается, поля раздела/объекта/вариации в центре подставляются по подсказке, у всех файлов семьи состояние сбрасывается на «хороший»/`idle`).
- **Ctrl+клик по файлу той же семьи** — сужает/расширяет набор файлов, к которому применится правка полей раздела/объекта/вариации (по умолчанию выбрана вся семья).
- **Ctrl+клик по файлу другой семьи** — игнорируется (подсвечивается вспышкой): смешивать семьи в одной правке нельзя.
- Поле раздела/объекта/вариации — текст только для чтения, редактируется через кнопку ✏ (или `Num7`/`Num4`/`Num1`) рядом; применяется к текущему набору Ctrl+выбора. «+ добавить» дописывает текст к вариации через «—» (для цвета/доп. уточнения), не пересоздавая остальное.
- **Клик по файлу той же семьи без Ctrl** — не меняет выбор для полей, а применяет к этому файлу текущее состояние (см. ниже).

## 4. Состояние: хороший / сломано / иконка

Два переключателя в центре — «Сломано» (`Num0`) и «Иконка» (`Num3`) — задают, какое состояние получит файл при следующем обычном клике по нему слева. По умолчанию у всех файлов семьи — «хороший» (`idle`), и любой новый выбор семьи слева сбрасывает оба переключателя обратно на «хороший». Включение одного переключателя выключает другой — файл не может быть одновременно и «сломан», и «иконкой».

## 5. Подтверждение и перенос

`✔ Подтвердить и перенести` (или `Enter` вне текстовых полей) переносит **всю исходную семью целиком** — каждый файл под своим накопленным именем `<раздел>_<объект>_<вариация>_<состояние>.<расширение>`. Если в папке назначения уже есть файл с таким именем, добавляется номер (как в Image Prep Tool). Перенос — это чтение байтов из источника, запись под новым именем в назначение и удаление исходного файла из источника; отменить уже выполненный перенос нельзя (`Ctrl+Z` отменяет только правки полей/состояний **до** подтверждения, не сам перенос файлов).

## 6. Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Enter` | Подтвердить перенос (вне текстовых полей); внутри поля правки — просто применяет введённый текст |
| `Ctrl+Z` / `Ctrl+Shift+Z` (и `Ctrl+Y`) | Отменить / вернуть последнюю правку (выбор, поля, состояние) |
| `Num7` / `Num4` / `Num1` | Начать правку поля Раздел / Объект / Вариация |
| `Num0` | Переключатель «Сломано» |
| `Num3` | Переключатель «Иконка» |

## 7. Скрипты (модули)

| Файл | За что отвечает |
|---|---|
| `01-core-utils.js` | Две независимые папки (File System Access API, IndexedDB `asset_renamer_fs`: ключи `sourceDir`/`destDir`), транслитерация/слаги |
| `02-grouping.js` | Разбор имени файла (`parseFileName`), сборка семей (`buildFamilies`), цвет раздела (`razdelColor`) |
| `03-state.js` | Активная семья, выбор для правки полей, `pending` (раздел/объект/вариация/состояние по каждому файлу), история отмены/возврата |
| `04-render.js` | Отрисовка трёх колонок, редактирование поля по месту |
| `05-actions.js` | Скан источника (`scanSource`), перенос с защитой от перезаписи (`confirmMove`) |
| `06-init.js` | Кнопки, клики, горячие клавиши (**всегда последним**) |

## 8. Как это видит Object Plan

Object Plan ищет превью вариации по префиксу `<id>_<вариация-en>` в `assets/refs/` и теперь (`refStateThumbs()` в `07-store.js`) отдельно проверяет суффиксы `_idle`/`_broken`/`_icon`, показывая в карточке объекта три бейджа вместо одного «есть/нет превью». Файл без суффикса (сохранён напрямую из Image Prep Tool, до переноса через Asset Renamer) засчитывается как `idle`.
