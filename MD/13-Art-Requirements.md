# Требования к картинкам

Это ТЗ для художника или для того, кто будет делать картинки для игры.
Если рисовать по нему, картинки встанут в игру без правок кода: механики уже работают и просто начнут показывать новые картинки.

---

## 1. Главное (менять нельзя без переделки кода)

| Параметр | Значение |
|---|---|
| Вид | **Сбоку, в разрезе** (как This War of Mine / Fallout Shelter). Без изометрии и без перспективы сверху |
| Масштаб | **1 см = 1 px.** Человек ростом 180 см ≈ 180 px |
| Высота комнаты | **3 м = 300 px** (от пола до потолка) |
| Ширина комнаты | 5–8 м = 500–800 px (выбирает генератор) |
| Этажи | Шаг между этажами **400 px** = комната 300 + перекрытие 100. Бункер идёт вниз, дома — вверх |
| Линия пола | Все объекты стоят **на линии пола**: низ картинки = пол |
| Экран | Базовое разрешение 1600×900. В бункере камера отдалена примерно до 0.5, на улице — 0.85 |
| Формат | **PNG с прозрачным фоном** (у стен и фонов прозрачность не нужна) |
| Свет | Ровный, мягкий, **без сильных бликов и резких теней в одну сторону**. Свет, день/ночь и лампы игра добавляет сама |
| Тон | Тёплый, приглушённый, грязный (постапокалипсис). Фон заметно **темнее** предметов, иначе предметы теряются |

## 2. Предметы, мебель, машины, растения, существа (через ОС)

Это всё, что есть в ОС (object-constructor). Картинки кладутся туда, потом синхронизация:
`python tools/sync_from_constructor.py ../object-constructor`

**Размер на экране** берётся из ОС: `real_width_cm` × `real_height_cm`.
- Ширина картинки в игре = `real_width_cm` px.
- Высота — по пропорциям картинки.
- Значит, пропорции картинки должны совпадать с реальными пропорциями предмета.

> **Правило для того, кто пишет `data/objects/<id>.json` напрямую (не через интерфейс ОС).**
> `behavior.real_width_cm`/`real_height_cm` — это **игровой** размер, он решается геймдизайном (каталог
> Object Plan, поле `sz`), а не картинкой. Реальные пиксели загруженного PNG (`appearance.imageWidth`/
> `imageHeight`) — **только информация о самом файле**, их нельзя использовать как источник или
> подсказку для `real_width_cm`/`real_height_cm`, и трогать эти два игровых поля при подключении
> картинки нельзя вообще (ни пересчитывать, ни «уточнять» по пропорциям файла). Картинка просто
> растягивается/сжимается, чтобы влезть в уже заданный игровой размер, пропорционально — это делает
> код показа, а не тот, кто готовит JSON. Если пропорции реального рисунка отличаются от
> `real_width_cm:real_height_cm` — значит рисунок нарисован не по этому ТЗ, это повод попросить
> перерисовать, а не повод менять игровые сантиметры под картинку.

**Рисовать:**
- вид строго сбоку (или сбоку с лёгким поворотом, но одинаково у всех предметов);
- предмет **без пустых полей вокруг**: синхронизация сама обрезает прозрачные края;
- разрешение — минимум в 2 раза больше размера в игре (стол 120 см → картинка ≥ 240 px в ширину). Синхронизация уменьшает до 512 px по большей стороне;
- низ предмета — ровно по низу картинки (ножки стоят на полу);
- **один предмет — одна картинка.** Не рисовать группой («три бака в ряд», «стеллаж с пятью банками») — ширина картинки растягивается до `real_width_cm`, а высота идёт по пропорциям самой картинки (см. правило выше), и у группового кадра пропорции почти всегда не такие, как у одного предмета: широкий кадр при растяжении по ширине становится ниже, чем должен быть один предмет (так `tank_water` — высокий резервуар 160×190 см — встал в игре ниже персонажа, потому что картинкой был кадр из трёх баков в ширину). Если нужно показать «склад из нескольких бочек» — это отдельный декоративный объект со своими `real_width_cm/real_height_cm`, а не вариация одного бака.

**Вариации и состояния** — в `object-constructor/assets/refs/<категория>/`, имя файла:

```
<id>_<вариация>_<состояние>.png
```

| Состояние | Что это |
|---|---|
| `idle` | обычный вид (обязательно) |
| `broken` | сломанный (если предмет ломается) |
| `icon` | иконка для инвентаря (квадрат, предмет крупно) |

Пример: `bed_single_derevyannaya_idle.png`, `bed_single_derevyannaya_broken.png`.
Каждый объект в мире получает случайную вариацию.

**Висящие вещи** (часы, щитки, окна, выключатели, лампы):
- на стене висят примерно на 150–190 см от пола, на потолке — у верхнего края комнаты;
- чтобы вещь висела, в ОС задай `custom.mount` = `wall` или `ceiling`.

**Ограничение:** предмет выше **270 см** в комнату не поставится (не влезет под потолок). На улице можно выше.

## 3. Персонажи

| Что | Куда | Размер |
|---|---|---|
| Персонаж в мире, вид сбоку | В ОС, объект `survivor_base` (поле картинки) | 100×180 см в ОС → рисовать ≥ 200×360 px |
| Портрет (экран «Персонажи») | `assets/portraits/survivor_base.png` (или `<uid>.png` — для конкретного человека) | ~400×500, вертикальный |

- Персонаж смотрит **вправо** (влево игра отражает сама).
- Сейчас персонаж — одна картинка; игра сама покачивает его при ходьбе.
- Покадровая анимация (ходьба, действия, сон) — отдельная задача, нужна небольшая правка кода. Если будет анимация: одинаковый размер кадров, 8–12 кадров на цикл ходьбы.

## 4. Стены комнат

`assets/rooms/<тип комнаты>.png`

- Размер **512×300** (5.12 × 3 м).
- **Бесшовно по горизонтали**: картинка повторяется по ширине комнаты.
- Без мебели и предметов — только стена (трубы, кабели, плитка, обои, грязь — можно).
- Тёмная: фон должен быть темнее предметов.

| Файл | Комната |
|---|---|
| `entrance.png` | шлюз бункера |
| `shelter_living.png` | жилая |
| `kitchen.png` | кухня |
| `storage.png` | склад |
| `workshop.png` | мастерская |
| `water_room.png` | насосная |
| `machine_room.png` | машинная |
| `greenhouse.png` | оранжерея |
| `house_living.png` | дом: комната |
| `bedroom.png` | дом: спальня |
| `bathroom.png` | дом: ванная |
| `garage.png`, `office.png`, `shop.png`, `medical.png` | дом: гараж, офис, магазин, медпункт |

Нет файла — стена рисуется кодом.

## 5. Улица

**Панорама — 3 слоя параллакса**, `assets/backgrounds/`:

| Файл | Слой | Пример размера |
|---|---|---|
| `skyline_1.png` | дальний (город на горизонте) | 2048×600 |
| `skyline_2.png` | средний | 2048×500 |
| `skyline_3.png` | ближний (заборы, деревья) | 2048×300 |

- Прозрачный фон сверху; **низ картинки = линия земли**.
- Бесшовно по горизонтали (повторяется).
- Небо (солнце, луна, облака, звёзды) рисовать **не надо** — его рисует игра и меняет по времени суток.

**Фасады домов** на улице сейчас рисуются кодом; картинки фасадов — отдельная задача (дом 560–860 px шириной, 420–680 px высотой, 1–2 этажа).

## 6. Перекрытия и лестницы

- Лестница берётся из ОС: объекты `ladder_metal` (бункер) и `stairs_wood` (дома).
- Растягивается на высоту этажа: **80×460 px** (от пола нижнего этажа до 60 px над полом верхнего).
- Рисовать **узкой и высокой**, чтобы растяжение не портило картинку.
- Перекрытия (бетонные плиты между этажами) пока рисуются кодом.

## 7. Интерфейс

| Что | Файл | Размер |
|---|---|---|
| Логотип | `assets/ui/logo.png` | 900×300, прозрачный фон |
| Иллюстрация главного меню | `assets/ui/menu_art.png` | 1920×1080 (левые ~600 px закрыты панелью меню) |
| Иконки интерфейса | `ui/icons/*.svg` | SVG, квадрат 24×24 (вода, еда, энергия, люди и т.д.) — заменить файлы с теми же именами |
| Цвета, шрифты, кнопки, рамки окон | `ui/theme.tres` | Меняется в Godot (редактор темы) |

Расположение элементов (где что на экране) — сцены `scenes/ui/*.tscn`, их можно переделать в Godot, механики не трогаются.

## 8. Физика и размещение (где что может стоять)

Не про картинки — про то, где объекту вообще разрешено оказаться в мире. **Все объекты должны иметь реальную физику** — это важное общее правило: нельзя, чтобы предмет висел в воздухе без опоры, торчал из пола, стоял там, где по смыслу его быть не может. Конкретные механизмы:

- **Лампы, часы, щитки, выключатели — крепятся к стене или потолку**, не стоят сами по себе. В JSON — `custom.mount: "wall"` или `custom.mount: "ceiling"` (см. §2 выше). У каждого такого объекта `custom.mount` обязателен — если его нет, при генерации/дошивке объекта это нужно сразу добавить, а не оставлять «как получится».
- **Резервуар/цистерна (`tank_water`, `water_tower`) не может стоять где попало.** Разрешённые комнаты — это список `rooms` у объекта в каталоге Object Plan (`behavior.allowed_room_types` в JSON): для `tank_water` — `water_room`/`machine_room`/`camp`, для `water_tower` (башня) — только `street`. Добавляя новый объект такого типа, `rooms` нужно продумать осознанно, а не копировать с чего попало.
- **Колодец (`well_hand`) — только на поверхности** (`rooms: street/camp/house_living`), под землёй/в бункере его быть не может — там, где нужна вода из-под земли в помещении, ставится **скважина или насос** (`water_pump`, разрешён в `water_room`/`machine_room`). Колодец и насос — разные объекты с разными правилами размещения, не вариации одного.
- **Грядки и растения (`planter_box`, `plant_potato`, `plant_wheat`, `plant_tree`, `bush_berry`) растут только там, где под ними грунт**, а не в произвольном месте комнаты. Сейчас в схеме ОС нет отдельного поля «нужен блок грунта под объектом» — для таких объектов это записывается в `custom.requires_block_below` (id блока, обычно `block_dirt`) как явное указание на будущее, пока игра не проверяет это сама. `hydro_rack` (гидропоника) — исключение, он водой без грунта, этот флаг ему не нужен.

## 9. Чек-лист перед тем, как отдать картинку

- [ ] Вид сбоку, как у остальных.
- [ ] Масштаб 1 см = 1 px (или ровно в 2 раза крупнее).
- [ ] Прозрачный фон, без пустых полей (кроме стен и фонов).
- [ ] Низ картинки = пол / земля.
- [ ] Свет ровный, без сильных теней в одну сторону.
- [ ] Стены и фоны — бесшовные по горизонтали и темнее предметов.
- [ ] Имя файла по правилам из этого документа.
