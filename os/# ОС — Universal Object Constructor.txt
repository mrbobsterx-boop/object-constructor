# ОС — Universal Object Constructor — справочник

Редактор **объектов** игры: рисует и собирает картинки (в т.ч. многослойные и анимированные), задаёт поведение, действия, инвентарь, разрушение, крафт, звук, материал блока и сохраняет объект в `data/objects/<id>.json` + спрайты в `assets/sprites/…`. Эти файлы читают Room Editor, Building Editor, Project Registry и игра (Godot). Заодно ОС пишет список своих категорий в `data/categories.json` — по нему Room Editor и реестр строят свои списки категорий.

- Файл запуска: `index.html` (двойным кликом, `file://`; для работы с папкой проекта нужен Chrome/Edge).
- Скрипты — обычные `<script>` с **общей глобальной областью видимости** (без `import`/`export`); номер файла = порядок загрузки. Порядок менять нельзя.

## 1. Как устроен интерфейс

| Область | Что там |
|---|---|
| **Шапка** | Отмена/Вперёд (undo/redo всего объекта); Новый; выбор и «Открыть» объект из проекта; Дублировать; Экспорт JSON; Импорт (ZIP сессии); Скачать всё (ZIP); Экспорт/Импорт каталога; «📁 Подключить папку проекта»; «💾 Сохранить в папку проекта»; «🔍 Проверить ссылки проекта» |
| **Левая колонка** | Категория объекта (17 кнопок); список «Каталог (сохранённые)» с миниатюрами |
| **Превью сверху** | Игровое превью объекта в реальном размере на фоне сетки 10 см (или на фоне выбранной комнаты); зум Ctrl+колесо, панорама ПКМ, перетаскивание объекта |
| **Вкладки** | Основное · Внешний вид · Поведение · Действия · Инвентарь · Крафт · Анимации · Разрушение · Материал (появляется только у категории «Блок / материал») · Дополнительно |
| **Правая колонка** | «Собранный объект» — живой JSON; «Компоненты»; пресеты (сохранить/применить/удалить шаблон настроек); теги |

### Категории
`character` Персонаж · `creature` Существо · `item` Предмет · `tool` Инструмент · `weapon` Оружие · `clothing` Одежда · `furniture` Мебель · `decor` Декор · `container` Контейнер · `workbench` Верстак · `machine` Машина · `building` Строительный объект · `block` Блок / материал · `door` Дверь · `plant` Растение · `resource` Точка ресурса · `special` Специальный.
Смена категории сбрасывает поля к значениям по умолчанию. **Блок / материал** сразу получает размер 100×100 см, столкновение `RECT`, физику `STATIC` и выключенное «Разрушаемый» (блок ломается кусками, а не по HP). У категории свой набор «стандартных» имён анимаций (например, у двери: closed / opening / open / closing / breaking / broken).

### Вкладки

**Основное** — ID, название (id строится из названия автоматически, пока его не правили вручную), подтип, Z-индекс, описание; «Картинка объекта»: вставка из буфера/файла/перетаскиванием, слои, трансформации слоя (рамкой за углы: масштаб/скос, жёлтая точка — поворот), кисть/ластик, «убрать пустое пространство», поля, изменение размера по высоте, нарезка спрайт-листа с отправкой в «Анимации»; «Коллизия» (режим `AUTO/FULL/MANUAL/NONE` и отступ в px).

**Внешний вид** — путь к картинке (собирается автоматически `категория/подтип/id_название.png`), режим графики (`IMAGE/PIXEL/ANIMATION`), «Скачать PNG».

**Поведение** — переносимый/размещаемый; **реальная ширина и высота в целых сантиметрах** — игровой размер объекта, не зависящий от пикселей картинки; кнопка **«🔗 Сохранить пропорции»** (по умолчанию включена, состояние запоминается): при вводе ширины высота подставляется по пропорциям картинки, при вводе высоты — ширина; если размер не совпадает с пропорциями, рядом появляется предупреждение и кнопка «Подогнать высоту по ширине»; режим размещения для Room Editor (`ANYWHERE` / `FLOOR_ONLY`); группа взаимозаменяемости; разрешённые типы комнат; столкновение, физика, интерактивность, вес; **свет** (радиус в м, цвет, интенсивность, форма круг/конус, направление, раскрытие, размытие), **тень**; потребности (еда, вода, сон, здоровье, стресс + параметры жажды), автономность, **восприятие** (зрение/слух в м), **перемещение** (скорость м/с), реакция на опасность, звук.

**Действия** — список действий по категории (USE, TAKE, DROP, OPEN …); у включённого действия: требования, время, нужный инструмент, расходуемый/выдаваемый предмет и количество, требуемый навык, эффекты (каталог эффектов пополняется). Ниже — урон / защита / износ.

**Инвентарь** — слоты, масса, тип хранения; для точки ресурса и контейнера — ресурс (тип, максимум, начальный объём, состояние, источник пополнения, самовосстановление).

**Крафт** — «Участвует в крафте» и конструктор рецепта: сетка 3×5, ингредиенты перетаскиванием из библиотеки, количество результата, зеркальный вариант; рецепт сохраняется в объект вместе с картинкой-схемой.

**Анимации** — «Визуальные состояния»: анимации (кадры) и статичные картинки-состояния (`idle`, `open`, `damaged`, `destroyed`…), имена латиницей. Для анимации: кадры (вставка, файл, перетаскивание, дублировать/удалить), нарезка спрайт-листа, обрезка/поля/масштаб сразу во всех кадрах, слои кадра (в т.ч. «→след.», «→все»), FPS, Loop / One Shot, воспроизведение, коллизия, **звук** (файлы, режим, громкость, радиус слышимости в м), **развитие навыков**, «Сохранить текущий кадр как картинку состояния». У персонажа/существа источник анимаций можно взять из Character Assembler.

**Дополнительно** — теги, «свои поля» (ключ-значение), произвольный JSON.

**Разрушение** (вкладка «Разрушение»): «Разрушаемый», HP, что происходит при уничтожении (убрать, останки, роняет предметы, обыскать, перенести, разлагается, роняет экипировку, заменяется другим объектом), порог повреждения (% HP), **повреждённый вид**, **разрушенный вид**, **анимация разрушения** (кадры/нарезка, FPS, спрайт-лист).

**Материал** (только категория «Блок / материал»; блок 1×1 м = 5×5 кусков по 20 см, куски ломаются по одному): **твёрдость** (относительная, 1 = обычная земля), **нужный инструмент** (id объекта), **срез внешних углов** (px = см, 0…10; пусто — общая настройка проекта из Room Editor), **что даёт один кусок** — текстовое поле, по строке `предмет; шанс %; от; до` (каждая строка бросается независимо; под полем показываются нераспознанные строки и предметы, которых нет в каталоге), **навык, влияющий на шанс**, **бонус к шансу за уровень навыка** (%) и **бонус от подходящего инструмента** (%). Картинка блока — основная картинка объекта (100×100 см); каждый кусок берёт свою 1/25 часть текстуры.

## 2. Данные

**Читает / пишет (папка проекта):**

| Путь | Что |
|---|---|
| `data/objects/<id>.json` | объект (запись «Сохранить в папку проекта») |
| `assets/sprites/<категория>/…png` | основная картинка, состояния, листы анимаций, повреждённый/разрушенный вид, лист анимации разрушения, схема рецепта |
| `assets/sounds/…` | звуки анимаций |
| `data/categories.json` | **запись**: список категорий `[{id,name}]` (порядок и названия из `CAT_LABELS`); пишется при подключении папки, сохранении и обновлении каталога, только если содержимое изменилось |
| `data/rooms/*.json` | только чтение: фоны комнат для превью; проверка ссылок (объекты, двери, типы блоков) |
| `data/characters/*.json`, `data/rigs/*.json`, `data/parts/…` | только чтение: связь с Character Assembler и проверка ссылок |
| `data/objects/.sessions/<id>.json` | только чтение: рабочий снимок объекта, если такой файл есть (редактор его не создаёт) |

**Без папки** (localStorage браузера): каталог `uoc_catalog_v1`, пресеты `uoc_presets_v1`, свои эффекты `uoc_custom_effects_v1`, свои навыки, использованные имена состояний `uoc_visual_names_v13`. Нужен только для работы без папки; при подключённой папке каталог берётся из `data/objects`.

### Формат `data/objects/<id>.json` (`schema_version: 4`)

Верхние ключи: `id, name, category, category_name, subtype, description, transform{layer}, appearance, behavior, actions[], action_settings{}, combat, inventory, resource, destruction, block, crafting, visuals, character_ref, animation_enabled, tags[], components[], custom`.

| Блок | Что содержит |
|---|---|
| `appearance` | `mode`, `asset` (путь), `imageWidth/imageHeight` (px картинки), `collision{type,padding,rect{x,y,w,h}}` — **px картинки** |
| `behavior` | флаги, `real_width_cm`, `real_height_cm` (**см**), `placement_mode`, `variant_group`, `allowed_room_types[]`, `light{radius_m,color,intensity,shape,angle,spread,softness}`, `shadow{absorption}`, `needs`, `autonomy`, `perception{vision{range_m},hearing{range_m}}`, `movement{enabled,speed_mps}`, `danger`, `makes_sounds` |
| `destruction` | `enabled, hp, damaged_threshold_percent, onDestroy[], damaged{image,…}, broken{image,…}, destroyAnimation{…}` — для обычных объектов (разрушаются целиком) |
| `block` | **только у категории `block`, иначе `null`**: `piece_size_cm` (20), `pieces_per_side` (5), `hardness`, `tool` (id или `null`), `bevel_px` (число или `null` — брать из настроек проекта), `drop_table[]` (`item, chance 0…1, min, max`), `drop_chance_modifiers{skill, skill_bonus_per_level, tool_bonus}` (доли) |
| `visuals` | `idle`, `animations[]` (`name, asset, frame_count, fps, loop, source, collision, sound{files,volume,radius_m,mode}, skill_progress`), `images[]` (`name, asset, width, height, collision, source_frame`) |

Длины — **метры** (`…_m`), скорость — м/с (`…_mps`), размер объекта — **сантиметры**. Пиксели в JSON — только размеры и коллизия исходной картинки (привязаны к текстуре). Старые файлы (радиусы/скорость в «px») читаются и делятся на 100.

### 02-image-document.js — класс `ImageDocument`

Слой = `{id, name, bitmap, w0, h0, visible, tl, tr, bl}`: три перетаскиваемые точки задают перенос, масштаб, поворот и скос; четвёртый угол вычисляется.

| Метод | Что должен делать |
|---|---|
| `constructor(canvas, handleLayerEl, opts)` | Создаёт документ: слои, размер, зум (по умолчанию 2), инструмент `MOVE`, кисть; подписывается на события мыши |
| `static blankBitmap(w,h)` / `static bitmapFromImage(img)` | Пустой холст / холст из картинки |
| `clear()` | Полностью очищает документ |
| `activeLayer` (геттер) | Активный слой |
| `addLayerFromImage(img)` | Первый слой задаёт размер документа; следующие вписываются по центру, не крупнее документа |
| `addBlankLayer()` | Пустой слой размера документа |
| `deleteActiveLayer()` / `mergeAllLayers()` | Удалить активный слой / склеить все в один |
| `flipActiveLayerH/V()` / `resetActiveLayerTransform()` | Отражение слоя / сброс скоса, масштаба и поворота |
| `moveLayer(layerId, dir)` | Переставить слой выше (+1) или ниже (−1) |
| `centerActiveLayer()` / `rotateActiveLayerBy(deg, center)` / `layerCenter(l)` | Центрирование / поворот вокруг точки / центр слоя |
| `docToLocal(l, px, py)` и матрицы | Перевод точки документа в координаты слоя (для кисти) |
| `drawLayer(ctx, l)` / `render()` | Рисует слой с матрицей / перерисовывает документ, ручки и вызывает `onChange` |
| `flatten()` | Склеивает видимые слои в один холст |
| `_recomputeAutoCollision()` | Прямоугольник непрозрачных пикселей (альфа > 10) — режим коллизии `AUTO` |
| `getCollisionRect()` | Прямоугольник коллизии по режиму: `NONE` — нет, `FULL` — весь документ, `AUTO` — по пикселям, `MANUAL` — заданный; плюс отступ |
| `trim()` | Обрезает пустые поля по непрозрачным пикселям (сводит слои в один) |
| `pad(top, bottom, left, right)` / `resizeToHeight(h)` | Добавить поля / изменить размер пропорционально по высоте |
| `serialize()` / `restore(state)` | Слои и состояние ↔ JSON (слои как data URL) — для кадров, истории, сессий |
| `setZoom(z)` | Масштаб отображения |
| `_renderHandles()` | Ручки: углы слоя и жёлтая точка поворота (инструмент `MOVE`); рамка и ручки коллизии (инструмент `COLLISION`, режим `MANUAL`) |
| `_paintAt(x, y, erase)` | Штрих кистью (круглая/квадратная) или ластиком в координатах слоя |
| `_bind()` | Мышь: перетаскивание ручек и слоя, рисование кистью, ластик, правка рамки коллизии |
| `attachBrushCursor(container)` | Круглый курсор размера кисти |

Инструменты: `MOVE`, `BRUSH`, `ERASER`, `COLLISION`.

## 6. Как связаны действия (типичный сценарий)

1. Выбрать категорию → задать название (id появится сам).
2. «Основное»: вставить картинку, убрать пустое пространство, проверить коллизию.
3. «Поведение»: **реальная ширина/высота в см**, свет, режим размещения.
4. При необходимости «Анимации», «Действия», «Инвентарь», «Крафт».
5. Подключить папку → «💾 Сохранить в папку проекта» → объект появляется в каталоге; его видят Room Editor и Building Editor.

## 7. Известные особенности и что нужно знать

- **Панель «Разрушение» открывается вкладкой «Разрушение»** (HP, «Разрушаемый», картинки «повреждён»/«разрушен», анимация разрушения). Раньше кнопки вкладки не было, из-за чего значения всегда оставались по умолчанию.
- `destruction.enabled` по умолчанию включён у **всех** категорий, кроме `block` (у блока он выключен: блок ломается кусками, см. вкладку «Материал»), поэтому по нему нельзя отличить разрушаемые объекты. Room Editor фильтрует блоки по категории `block`.
- Картинки повреждённого/разрушенного вида блока Room Editor больше не использует: блок рисуется по маске кусков из основной картинки. У обычных объектов `damaged`/`broken` читает игра. Альтернатива — статичные состояния `damaged` / `destroyed` / `broken` во вкладке «Анимации» (попадают в `visuals.images[]`).
- **Список категорий зашит в коде** (`CAT_LABELS`, кнопки в `index.html`, `STANDARD_ANIMATIONS`); в файл `data/categories.json` он только выгружается. Новая категория = запись в этих трёх местах. Id `block` зашит в Room Editor и реестре.
- Блок в ОС — это объект с картинкой 100×100 см. Что попадает в комнату, задаёт Room Editor; какие куски и когда ломаются, решает игра.
- `07-object-io.js` подписан «MODULE 07 — CRAFTING», а содержит ещё и ядро, историю, экспорт, папку проекта, проверку ссылок, INIT.
- Поле id заполняется сразу при загрузке страницы (`object_<время>`) и заменяется транслитом названия, пока его не правили вручную.
- Реальный размер объекта задаётся в **целых сантиметрах** и не зависит от пикселей картинки, но картинка растягивается ровно под ширину×высоту. Поэтому включена «Сохранить пропорции»: пропорции берутся из основной картинки, а если её нет — из кадра анимации или картинки-состояния (нет ни того, ни другого — поля независимы). Для анимированных существ это размер **всего кадра**, а не тела (кадр 512×512 со «полями» даёт размер вместе с полями). Если размер не задан (0), Room Editor берёт размер картинки (1 px = 1 см).
- Состояние кнопки «Сохранить пропорции» хранится в `localStorage` (`uoc_keep_aspect`), а не в JSON объекта.
- Кисть, ластик и коллизия работают в пикселях картинки; `appearance.collision` — px исходной картинки, не мировые единицы.
- Рабочие снимки `data/objects/.sessions/<id>.json` редактор только читает при открытии, сам не создаёт.
